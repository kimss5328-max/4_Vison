# 1. 개요
라벨링 프로젝트의 단계별 흐름 규칙과 권한을 판정하는 비즈니스 로직 모듈입니다. Tkinter GUI 화면이나 파일 I/O 조작을 전혀 다루지 않으며, 사용자 목록(`config.PEOPLE`)과 이미지별 이력 CSV(`read_events`)를 기반으로 **누가(작업자/검수자) 어떤 이미지를 어디로 보낼 수 있는지**에 대한 권한 검증 및 작업 이력 가공(`Flow` 클래스)만을 순수하게 담당합니다.

# 2. 파일 간 연결 구조
- 상속 관계: 없음 (독립 판정 모듈)
- 외부 의존성 및 호출 관계: `src.config`의 설정 상수(`INFO_FIELDS`, `PEOPLE`, `ROLE_NAMES`, `STAGE_LABELS`, `WORKER_TARGETS`, `REVIEWER_TARGETS`, `WORKER_EDITABLE`, `DEFAULT_TARGET`)를 참조하며, 주로 `StorageMixin`이나 UI 패널 등에서 권한 체크 및 이력 표시에 호출됨

# 3. 주요 상태 변수 및 함수

| 분류 | 함수 / 클래스 | 역할 |
| :--- | :--- | :--- |
| **인물 관리** | `person_label`, `people_labels`, `person_by_label` | 사용자 정보를 드롭다운 표시용 문자열로 변환하거나 라벨을 통해 인물 딕셔너리를 역참조 |
| **설정 검증** | `check_people()` | 프로그램 시작 시 `config.PEOPLE`을 검사하여 ID 중복이나 역할 오타, 필수 필드 누락 시 `ValueError` 발생 |
| **이력 파싱** | `read_events(csv_path)` | 이미지별 이력 CSV를 읽어와 저장 1회당 1개의 딕셔너리 이벤트 목록(오래된 순)으로 그룹화 및 반환 |
| **권한 및 흐름** | `Flow` 클래스 | 특정 이미지의 현재 단계(`stage`)와 이력(`events`)을 바탕으로 액션 가능 여부(`can_act`), 타겟 단계(`targets`), 기본 선택 단계, 이력 요약(`history_lines`) 등을 판정 |

# 4. 주요 실행 흐름
- **사람 설정 무결성 검사 (`check_people`):**
  - 모듈 로드 시점에 `check_people()`을 즉시 실행하여, 정의된 인물 데이터의 ID 유일성 및 역할(`ROLE_NAMES`) 정합성을 엄격하게 사전 검증합니다.
- **이력 그룹화 (`read_events`):**
  - CSV 파일은 바운딩 박스 단위로 행이 기록되므로, 동일한 시각(`saved_at`)과 단계(`stage`)를 가진 연속 행들을 하나의 저장 이벤트로 묶어 효율적으로 분석합니다.
- **권한 및 타겟 판정 (`Flow` 클래스):**
  - `can_act(person)`: 작업자는 `final` 단계나 작업 불가 단계를 수정할 수 없으며, 검수자는 모든 이미지 작업을 자유롭게 수행할 수 있도록 역할별 권한을 판정합니다.
  - `targets(person)`: 작업자(`WORKER_TARGETS`)와 검수자(`REVIEWER_TARGETS`)가 검수 상태 드롭다운에서 선택할 수 있는 허용 단계를 반환합니다.
  - `history_lines()`: 단계별 최초 저장자(`top`)와 이후의 이동 및 수정 이력(`log`)을 깔끔한 텍스트 라인으로 조합하여 UI 패널에 제공합니다.
