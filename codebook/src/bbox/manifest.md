# 1. 개요
프로젝트 전체 진행 상황과 이미지별 라벨링 이력을 관리하는 데이터 대장(Manifest) CSV 파일을 이미지 1장당 1행 기준으로 갱신(Upsert)하는 백엔드 데이터 처리 모듈입니다. Tkinter GUI 화면과 완전히 독립되어 있으며, 순수 계산 및 안전한 파일 입출력(임시 파일 작성 후 교체)만을 담당합니다.

# 2. 파일 간 연결 구조
- 상속 관계: 없음 (독립 모듈)
- 외부 의존성 및 호출 관계: `src.config`의 설정 상수(`MANIFEST_HEADER`, `STAGE_STATUS`, `QA_WAIT`, `SPLIT_NAMES`)를 참조하며, 주로 `StorageMixin` 등 데이터 저장 로직에서 호출됨

# 3. 주요 상태 변수 및 함수

| 분류 | 함수 / 예외 클래스 | 역할 |
| :--- | :--- | :--- |
| **예외 정의** | `ManifestFormatError` | 기존 manifest 파일의 열(Field) 구성이 현재 형식과 다를 때 발생하는 커스텀 예외 |
| **경로 유틸** | `split_of(path)` | 이미지 파일 경로에서 하위 디렉토리를 역탐색하여 `train` 또는 `validation` 분할(Split) 정보를 추출 |
| **데이터 조회** | `read_rows`, `find_row` | CSV 파일에서 전체 행을 읽어오거나(`read_rows`), 특정 이미지 키(`dataset`, `split`, `file_name`)에 해당하는 행을 검색 |
| **행 생성/갱신** | `build_row`, `upsert` | 저장 단계별 상태 규칙에 따라 새로운 행 데이터를 조합하고(`build_row`), 기존 행이 있으면 제자리 수정(Upsert)하며 없으면 추가한 뒤 임시 파일을 통해 안전하게 교체 |

# 4. 주요 실행 흐름
- **분할 정보 파악 (`split_of`):**
  - 이미지 경로의 디렉토리 구조를 역순으로 분석하여 `SPLIT_NAMES`에 매핑되는 원본 데이터셋 분할(`train`/`validation`)을 판별합니다.
- **행 데이터 구성 (`build_row`):**
  - 저장 단계(`stage`)에 따른 상태(`status`)와 QA 상태(`qa_status`)를 결정합니다. 재작업 요청(`view`)인 경우 직전 상태를 유지하고 QA 상태는 대기(`QA_WAIT`)로 설정합니다.
  - 최초 저장된 작업자(`worker`) 정보는 한 번 지정되면 변경되지 않도록 유지하며, 검수 사유(`review_reason`) 역시 빈 값이 입력될 경우 기존 값을 보존합니다.
- **안전한 업서트 및 교체 (`upsert`):**
  - 식별 키(`source_dataset`, `original_split`, `file_name`)를 기준으로 기존 행의 존재 여부를 파악하여 제자리에서 갱신하거나 리스트 하단에 추가합니다.
  - 파일 쓰기 도중 프로그램이 종료되더라도 기존 데이터를 보호하기 위해 먼저 `.tmp` 임시 파일에 기록한 후 `os.replace`를 통해 원자적으로 교체합니다.

# 5. 확인 및 개선 사항
- 행의 기존 순서를 최대한 유지하며 제자리 수정(In-place update)하도록 구현되어 있어, Git 버전 관리 시 불필요한 diff 충돌을 최소화합니다.
- 열 구성이 일치하지 않을 때 `ManifestFormatError`를 발생시켜 데이터가 잘못 덮어씌워지는 사고를 사전에 방지하도록 견고하게 설계되었습니다.
