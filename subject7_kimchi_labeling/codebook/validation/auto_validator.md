# 1. 개요
프로젝트 폴더를 열 때 원본 이미지와 YOLO 라벨(`TXT`) 쌍의 무결성을 기계적으로 검사하고, 오류나 경고 사항을 CSV 리포트로 누적 저장하며, Tkinter 팝업과 콘솔을 통해 사용자에게 안내하는 자동 검증(Validation) 모듈입니다.

# 2. 파일 간 연결 구조
- 상속 관계: 없음
- 호출 구조: `FolderMixin` 내에서 백그라운드 스레드로 호출되어 `run_validation(img_root, pj, parent_window)`를 실행함.

# 3. 주요 상태 변수

| 분류 | 주요 상수 및 변수 | 역할 |
| :--- | :--- | :--- |
| **허용 클래스** | `ALLOWED_IDS`, `C4_ID` | 허용된 클래스 ID 집합(`{0, 1, 2, 3, 5, 6}`) 및 존재 시 리뷰를 권장하는 4번 클래스(`UNUSED_CLASS`) 관리 |
| **리포트 경로** | `REPORT_DIR`, `REPORT_FILE` | 검증 결과가 누적 저장되는 `reports/validation_report.csv` 경로 |
| **검증 헤더** | `REPORT_HEADER` | CSV 리포트에 기록될 열 구조 정의 (`checked_at`, `img_root`, `file`, `level`, `check`, `detail`) |

# 4. 주요 실행 흐름
- **쌍(Pair) 및 무결성 검사 (`_check_pair`, `_check_image`, `_check_txt`):**
  - 이미지와 TXT 파일의 존재 여부를 대조하고 불일치 시 `WARNING` 또는 `ERROR`를 기록합니다.
  - 이미지 파일의 정상 오픈 여부 및 유효한 크기(`w > 0`, `h > 0`)를 검증합니다.
  - 라벨 TXT 파일의 포맷(5개 열 구성), 숫자 파싱 가능 여부, 클래스 ID 범위, 좌표 범위(`0.0 ~ 1.0`), 너비/높이 양수 여부를 줄 단위로 정밀 검사합니다.
- **리포트 저장 및 출력 (`run_validation`):**
  - 발견된 모든 이슈를 `reports/validation_report.csv` 파일에 **추가(Append)** 방식으로 기록합니다.
  - 콘솔에 상세 검증 내역을 출력하고, 오류가 존재할 경우 Tkinter 팝업창(`messagebox.showwarning`)을 통해 요약 정보를 직관적으로 안내합니다.
  - 검사 과정에서 예외나 오류가 발생해도 프로그램 로딩을 중단하지 않고 정상 동작하도록 설계되어 있습니다.

# 5. 확인 및 개선 사항
- 폴더 로딩 시 메인 UI를 차단하지 않도록 데몬 스레드에서 백그라운드로 실행되므로 대용량 데이터셋에서도 로딩 속도 저하가 없습니다.
