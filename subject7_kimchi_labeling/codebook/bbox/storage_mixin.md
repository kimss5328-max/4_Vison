# 1. 개요
데이터 라벨링 작업의 상태를 디렉토리 구조로 관리하고, 진행 과정(단계 이동) 및 작업 내역을 CSV 파일에 누적 기록(Append)하는 저장 시스템 모듈입니다.

# 2. 파일 간 연결 구조
- 상속 관계: 없음 (GUI 메인 클래스 등에 `StorageMixin` 형태로 다중 상속되어 사용됨)

# 3. 주요 상태 변수

| 분류 | 주요 상수/메서드 반환 | 역할 |
| :--- | :--- | :--- |
| **기록 포맷** | `CSV_HEADER`, `MANIFEST_HEADER` | 이미지별 이력 및 전체 진행 대장(CSV)의 열(Column) 헤더 정의 |
| **단계 우선순위** | `LOCATION_ORDER` | 현재 이미지의 저장 단계를 파악할 때 역순(최종->초기)으로 탐색하기 위한 튜플 |
| **클래스 상태** | `self.review_status` | 이미지별 현재 검수 상태 캐싱 딕셔너리 (`{경로: 단계}`) |
| **클래스 상태** | `self.done`, `self.passed` | 저장된 이미지, 혹은 지나간 이미지를 추적하는 세트(Set) |

# 4. 주요 실행 흐름
- **초기화 및 경로 설정 (`ask_out_dir`, `set_out_dir`):**
  - 작업 대상이 되는 결과 디렉토리(기본: `visol04/`)를 설정하고, `data/raw`, `work/`, `reviews/` 등 하위 디렉토리를 생성합니다.
  - 선택한 원본 이미지를 `data/raw` 폴더로 복사(`import_raw`)합니다.
- **자동 저장 (`autosave_work`):**
  - 라벨(박스) 편집 시마다 `work/1차` 등의 작업 디렉토리에 YOLO 형식(`.txt`)으로 즉시 임시 저장하여 진행 상태를 유실하지 않도록 합니다.
- **정식 저장 (`save`):**
  - 1차/2차/review/final 중 지정된 검수 단계로 현재 이미지를 이동(기존 폴더에서 삭제 후 새 폴더로 복사)합니다.
  - 박스의 좌표를 YOLO 포맷으로 변환해 텍스트로 저장하며, review 단계일 경우 박스가 그려진 미리보기 이미지를 생성합니다 (`_write_preview`).
  - 이미지별 작업 이력과 전체 진행 내역을 CSV에 **수정 없이 추가(Append)** 형태로 기록합니다 (`_append_history`, `_append_manifest`).
  - 이슈 노트가 있으면 `issues/` 폴더에 관련 파일 사본과 내용을 덧붙입니다 (`_append_issue`).

# 5. 확인 및 개선 사항
- 모든 파일 I/O 기록 방식이 기존 내용을 덮어쓰지 않고 추가(Append)하는 방식으로 일관되게 설계되어 있어, 작업의 모든 히스토리(1차 작업F자, 1차 검수자 등)가 유실 없이 보존됩니다.
- 한글 폰트를 지원하기 위해 OS 별로 지정된 `PREVIEW_FONTS`를 순회하여 찾고 렌더링에 반영하는 로직이 적용되어 있습니다 (`preview_font` @lru_cache 적용).
- 디렉토리 이동 시 `os.remove` 등을 사용하여 직접 이동(Move)이 아닌 삭제 후 복사(Copy/Write) 방식으로 단계를 이전합니다.
